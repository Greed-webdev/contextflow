# ПРАВИЛА ТЕСТИРОВАНИЯ — ContextFlow

Что проверяем, чем проверяем и когда имеем право сказать «готово».

---

## 1. Что приходит от владельца и как это тестится

### Сцены / партии диалогов (тексты + судьи)
- Меняем **только** `judge` / `task` / `tr`. Структуру узлов, имена узлов и вёрстку не трогать.
- Ход — это **цель** («поздоровайся и назовись»), а не диктовка конкретной фразы. Диктовка запрещена.
- Судья обязан принимать **свободный** ответ по смыслу: порядок слов не важен, лишние слова игнорируются, точное совпадение с `best` НЕ требуется.
- Текстовые правки — только с сохранением **судейской семантики**: каждая ветка, которую принимал старый судья, принимается и новым.

### Ревью / промпты (файлы в `uploads/`)
- Каждый пункт ревью = отдельная проверка: воспроизводим её на конкретном узле/фразе.
- Не «поправил по ревью», а «проверил каждый пункт ревью отдельно».

### Механика, которую нельзя ломать (регресс-список)
1. «Не знаю» → проговаривается `best`, диалог идёт дальше.
2. Подсказка появляется **только после 2 непониманий** (`huh`).
3. Сцена заканчивается **только через прощание** (узел с `next:null`).
4. `best` никогда не показывается как «правильный ответ» до попытки.
5. Автопроверка голоса: копится лучший результат за попытку (`bestHeard/bestScore`).
6. Ввод текста: никакого сжатия/фиксации/прибивки поля; плавный подскролл только при реальном перекрытии клавиатурой.
7. В диалоге: вопрос и поле ввода рядом, компактный 🔊 у реплики, «Не знаю» — заметная кнопка.

## 2. Чем тестируем (инструменты)

| Инструмент | Что делает | Команда |
|---|---|---|
| `node --check` | синтаксис правленого js — прежде чем что-либо запускать | `node --check js/app.js` |
| `qa/flow-test.js` | **эталонный прогон**: автопроход всех диалогов по всем веткам фразами урока | `node qa/flow-test.js` → ждём «ИТОГ: N pass, 0 fail» |
| `qa/adversarial.js` | **враждебный прогон**: ~80 живых фраз новичка на каждый судью (мусорные имена, вежливые «no», голые yes, русские вставки) — ищет слепые зоны, не обязан быть 100% | `node qa/adversarial.js` |
| `qa/проверить-сверщика.js` | чекер по конкретному ревью/правке | `node qa/проверить-сверщика.js` |
| версия в профиле | самопроверка кэша у пользователя: после деплоя в профиле меняется метка (`#pf-ver`, сейчас v24) | смотреть в `index.html` |
| GitHub API | содержимое `main` после деплоя сверяем через API, не через «глаза на сайте» | `api.github.com/.../contents/...` |

## 3. Правило «готово» (заведено 2026-09-06)

Слово «готово» пишется владельцу **только после деплоя** и только если:

1. `node --check` — без ошибок;
2. каждый изменённый узел/диалог прогнан **дважды**:
   - эталонный проход (`flow-test`) — доходит до конца: `0 fail`;
   - враждебный проход (`adversarial`) — слепые зоны просмотрены, критичных дыр нет;
3. деплой выполнен (`обновить-сайт.sh`), метка версии поднята.

«Написано в файле» ≠ «готово».

## 4. Если что-то сломалось

- Откат к последней рабочей копии. Не чиним «ещё одним полным файлом» и патчем на патч.
- Проблемы при вводе/клавиатуре — возвращаем прежнее поведение; костыли (`body fixed`, `--kbd`, `syncKbd`) запрещены как класс.
- Одна зона за заход: правим `theme.css` — не лезем «заодно» в `lessons.js`.

## 5. Известная слабость (зафиксирована, чинится по плану)

Продакшен-судья на враждебном наборе принимает ~8–10% живых фраз новичка.
Это системная проблема, чинится **перед/во время** раскатки на 60 диалогов —
не в фоновом режиме и не ценой поломки текущих сцен.

## Чек «источник истины» (договорились с оценщиком, 2026-09-14)

Перед любым новым баг-репортом по демкам репорт обязан содержать:
1. откуда загружен файл (точный URL/путь);
2. SHA файла, который реально исполнялся;
3. кусок `judge` соответствующего узла из раннер-лога.

Без этого баг-репорт считается ненавостимым: спор «старый снапшот» закрыт
на blob `c1cd440` (демо-6, HEAD `9a59b0b`) — файл был актуальный.

## UI-логи — «глаза» на интерфейсе (с 2026-09-16)

`node qa/ui-log.js` — головless-прогон ВСЕГО проекта через DOM-шим:
каждый уровень всех 5 этапов, каждый диалог проговаривается образцом через
настоящий UI-путь (поле → «Ответить» → «Дальше/Завершить»), плюс мусорные
ответы (путь ошибки) и «Не знаю». Любое исключение = строка ✗ в логе,
тихий обрыв диалога = строка ⚠ (недоговорённые узлы).
