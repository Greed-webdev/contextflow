## 1. Отрицание цвета читается наоборот — блокирующий

**Где:** узел `pick` сцены S2.

```js
judge(w){ const b=has(w,'black'), r=has(w,'red');
    if(b&&r) return {br:'both'};
    if(b) return {br:'black'};
    if(r) return {br:'red'};
```

Проверено стендом:

| Ввод | Результат | Должно быть |
|---|---|---|
| `not black, red` | `both` — «по одному каждого цвета» | красный |
| `no red` | `red` — выбран красный | чёрный либо переспрос |
| `I do not want red` | `red` — выбран красный | чёрный либо переспрос |

Человек говорит «не хочу красный» — ему кладут красный. Это худший вид ошибки в тренажёре: игрок получает подтверждение, что его поняли, хотя поняли наоборот.

**Что сделать.** Заведи помощник, который проверяет слово с учётом отрицания перед ним, и примени его вместо голого `has`. Логика: слово считается выбранным, только если в пределах двух слов перед ним нет `no`, `not`, `never`, `without`.

Ожидаемое поведение после правки:

- `not black, red` → ветка `red`
- `no red` → ветка `black`, либо переспрос, если чёрный тоже не назван явно
- `I do not want red` → то же
- `black` → ветка `black`
- `red` → ветка `red`
- `black and red` → ветка `both`

## 2. Проверка сдачи принимает отказ как согласие — блокирующий

**Где:** узел `change` сцены S1.

```js
judge(w){ if(has(w,'wrong','short','mistake')||(has(w,'not','no')&&!has(w,'thanks','thank'))) return {br:'recheck'};
    if(has(w,'thanks','thank')||has(w,'right','ok','okay','fine','correct')) return {br:'ok'}; return {huh:1}; },
```

Условие `has(w,'not','no') && !has(w,'thanks')` рассыпается, как только человек вежлив:

| Ввод | Результат | Должно быть |
|---|---|---|
| `no thanks` | `ok` — «Пожалуйста, хорошего дня» | `recheck` — пересчитать |
| `no, thank you` | `ok` | `recheck` |
| `wrong, thanks` | `recheck` | верно |

«No thanks» на вопрос о сдаче — это «нет, неверно», а не благодарность.

**Что сделать:** убери завязку на отсутствие `thanks`. Отрицание должно засчитываться независимо от вежливых слов. Ветка `recheck` — если есть `wrong`, `short`, `mistake`, либо отрицание рядом со словами `right`/`correct`/`ok`, либо голое `no`/`not` в начале фразы.

## 3. Размер: «not small» и «extra small» дают маленький

**Где:** узел `size` сцены S2.

```js
judge(w){ if(has(w,'small','little')) return {br:'s'};
    if(has(w,'medium','large','big')) return {br:'l'};
```

- `not small` → ветка `s` (маленький)
- `extra small` → ветка `s`

**Что сделать:** примени тот же помощник с проверкой отрицания, что и в пункте 1.

Отдельно: `medium` сейчас уходит в ту же ветку `l`, что и `large`, и реплика «Here you are» теряет размер. Добавь для `medium` свою ветку с ответом вроде «A medium one. Here you are», по образцу ветки `s`.

## 4. «Five hundred» превращается в пять

**Где:** помощник `FLOWNUM`, используется в узлах `count`, `twelve`, `extra` сцены S1.

```js
const FLOWNUM = (w, digits) => {
  if (digits && digits.length) return digits[0];
  for (const x of w) if (x in NUM) return NUM[x];
  return null;
};
```

Берётся первое числительное, остальное игнорируется:

- `five hundred` → 5, ветка `five`, продавец продаёт пять штук вместо пятисот
- `two and three` → 2

**Что сделать:** научи `FLOWNUM` собирать составные числа — если после числительного идёт `hundred` или `thousand`, умножать. Если во фразе несколько несвязанных чисел (`two and three`) — возвращать признак неоднозначности, чтобы узел переспросил.

Заодно в узле `count`: ввод `0` сейчас уходит в `othernum` («продаём по пять штук»). Ноль — не количество, логичнее переспрос.

## 5. Узел `rest` не умеет «мне нужно ещё»

**Где:** узел `rest` сцены S2.

```js
judge(w){ const extra=has(w,'more','also','need','want','another');
    if(!extra&&(has(w,'no','nothing')||has(w,'all','everything','that'))) return {br:'all'};
    return {huh:1}; },
```

Ветка на продолжение покупки просто отсутствует. Всё, что не «это всё», отбивается:

- `yes I need more` → `huh`
- `I want another one` → `huh`
- `no I need more` → `huh`

Игрок, желающий добавить покупку, упирается в стену и через две попытки получает подставленный ответ «No, that is all» — то есть игра решает за него.

**Что сделать:** добавь в `rest` вторую ветку — например `more`, ловящую `more`, `another`, `also`, `need`, `want`, `one more`. Ответ вроде «Of course. What else do you need?» с переходом в узел `pick` либо в новый короткий узел выбора. Пропиши её в `tr`.

## 6. Петли без выхода

Проверено: четыре круга подряд без продвижения.

- `count` → ветка `othernum` → снова `count`
- `twelve` → ветка `twenty` → снова `twelve`
- `pick` → ветка `colour` → снова `pick`

В живом UI спасает кнопка «Дальше» после двух промахов, но сам цикл бесконечен: игрок, упорно называющий неверное, крутится там навсегда.

**Что сделать:** заведи счётчик попыток в `mem` (например `mem._loop`) и на третьем заходе в ту же ветку выдавай уступку — продавец соглашается либо предлагает готовый вариант, и диалог движется дальше. Это ближе к живому разговору: настоящий человек не повторяет одно и то же бесконечно.
