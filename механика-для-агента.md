## 2. Что уже внедрено (v22, залито на сайт)

Живой сайт: https://greed-webdev.github.io/contextflow/ (версия v22, озвучка 2403 фразы).
Репозиторий: `Greed-webdev/contextflow`:
- ветка `main` — только живой сайт (деплой через `обновить-сайт.sh`),
- ветка `workspace` — вся разработка + эти файлы.

### Формат данных (js/lessons.js, уровень 135)
```js
{ type:'dialog', variant:'lost', title:'Потерял вещь', scene:'street', cefr:'...', intro:'...',
  lost:{
    ruThings:{ phone:'телефон', bag:'сумку', ... },          // предметы: id -> русская форма
    alias:{ telephone:'phone', mobile:'phone', ... },         // синонимы
    lose:['lost','lose','losing','missing','gone','stolen','left','forgot',...],
    places:[...], colors:[...], sizes:[...],
    greet:['hi','hello',...], bye:[...], thanks:[...],
    nodes:[
      { id:'greet', kind:'greet', task:'Поздоровайся и назови себя.', them:'Hello! Can I help you?', ruThem:'...', best:'Hi, my name is Anna.', opts:['Hi, my name is Anna.','Hello, I am Anna.'] },
      { id:'what', kind:'what', ... },      // what / whatthing / where / desc / agree / end
      ...
    ]
  }}
```

### Движок (js/app.js)
- `Lesson.start()` — `total` = 6 для `variant:'lost'`.
- `lostInit()` — строит экран (шапка «Обстановка» из `intro`, чат `#chat`, блок `#answers`, кнопка «Слушать реплику» озвучивает последнюю реплику собеседника).
- `lostFind(id)`, `lostNext()` — маршрут по графу: `greet → what → (есть предмет: where | нет: whatthing→where) → (место 'here' нет: search | есть: callplace) → end`.
- `lostNode()` — показать реплику собеседника (`them`+озвучка) → `lostAsk(node)`.
- `lostAsk(node)` — весь интерактив:
  - **свободный ввод** (textarea, можно «Надиктовать» если есть микрофон) + кнопка «Ответить»;
  - **«Не знаю — покажи, как сказать»** → готовые фразы из `opts` (или `[best]`); клик по варианту тоже прогоняется через `judgeNode` и **сам выбирает ветку** (сказал wallet — дальше про кошелёк);
  - **разбор по смыслу** (`judgeNode`), а не по буквам; три исхода:
    - `ok` — «Тебя поняли.» (+ очки, озвучка образца, «Дальше»);
    - `short` — «Поняли. Идём дальше.» (одно слово/неполная фраза **принята**, рядом «Целиком это звучит так: …»);
    - `no` — «Это не про то.» → первый промах: кнопка **«Исправить ответ»** (жизнь не снимается, реплика убирается); второй промах: Miss + потеря жизни + показать образец;
  - русский ввод → «Похоже на русский — попробуй по-английски.»;
  - память диалога: `this.lMem` — `{name, thing, place}`; предмет **никогда не навязывается сценарием** и незнакомое слово **не подменяется** (что потерял — выбирает игрок);
  - правила узлов: где — одно слово места достаточно (`cafe` ок); описание — цвет/размер, слова не считаются (`black big` ок); финал — «Попрощайся.», `bye have a good day` принимается, «С "thanks" было бы теплее»;
  - в конце — кнопка «Завершить» (не «Дальше»), экран «уровень пройден»;
  - `finish()` при `no`-ветках корректен.
- Озвучка реплик: `Voice.say` через `assets/voice/index.json` (vmap); в Telegram speechSynthesis нет — звучит только заранее начитанное. Новые фразы добавлять через `tools-voice.py` (piper-tts + ffmpeg из imageio; системного ffmpeg в песочнице нет — скрипт уже переведён на imageio-ffmpeg).

### Ключевые семантики (сверять при расширении)
- `greet`: имя ловится как не-служебное слово; запоминается с заглавной.
- `what`: предмет (self или alias) + глагол потери → ok; только предмет → short (принято, предмет запомнен); глагол без предмета → уточняющий `whatthing`.
- `whatthing`: неизвестное → «Такого слова не знаю. Скажи проще: phone, bag, wallet, keys, passport.» — **не подменять**.
- `where`: без места → short и `place=null` → ветка `search` («будем искать рядом»), иначе `callplace`.
- `end`: thanks+bye → ok; только bye → ok + «С thanks теплее»; только thanks → ok; всё прочее → short (засчитано).

### Что НЕ должно вернуться в UI
- Карточки «Правка 1/Правка 2», строка «Попробуй: …» (владелец велел убрать — это были только пояснения для демо).
- Никаких отладочных строк «память диалога → …» (только `console`, не в DOM).

## 4. Что нужно сделать (задача владельца) — по шагам, с учётом ПРАВИЛА 50

Правило 50 (критично!): **сначала показать на деле (демо) → владелец одобряет → только потом в рабочий код.** Демо отдельными файлами (`демо-N.html`), в `js/` не трогать до одобрения. В конце каждого захода — сводка «Исправил / Добавил / Не получилось». Не врать «ошибок нет» — сначала воспроизвести, показать фактами.

Рекомендуемый план (обсудить с владельцем, не делать молча):

1. **Обобщить движок** (сейчас `lostInit/lostAsk` — частный случай «потерял вещь»; узлы захардкожены по kind'ам). Превратить в общий графовый движок диалога: `type:'dialog', variant:'graph'`, `nodes[]`, `start`, `next(mem)`, per-node `kind` или своя `judge`/`check`-функция + `opts` + озвучка. Обратная совместимость: старый `turns[]`-формат продолжает работать (`askTurn`), старый `variant:'lost'` тоже.
2. **Демо-5**: переписать на новом движке **уровень 3 «Первое приветствие»** (это «тот самый третий уровень» из жалоб владельца: приветствие/имя/прощание должны приниматься свободно, вежливые ответы по смыслу, «Разговор о семье» и прочие ранние диалоги — кандидаты). Показать владельцу демо → правки → одобрение.
3. После одобрения — **внедрить движок** в `js/app.js` + перевести «Первое приветствие» в рабочих данных, прогнать проверки 1–4, залить.
4. **Раскатывать по диалогам партиями** (60 штук; каждому нужен свой граф/ветки/семантика — это контентная работа): приоритет — с начала курса (ур. 3, 6, 9, 13…), по одной зоне за заход (правило 3), ломатель после каждой партии. Не «одним файлом на всё».
5. Озвучка новых реплик: гонять `tools-voice.py` (он собирает `turns`, `options`, и `lost.nodes.them/best/opts`).

Важно: не всё обязано ветвиться одинаково глубоко — минимум для «разговор идёт за тобой»:
- задание не диктует точную фразу (что сказать — решает игрок, вариант в `opts` только под «Не знаю»);
- одно слово/короткая фраза не блокируется (полная фраза показывается рядом);
- разбор по смыслу: синонимы, вежливые формулы целиком, неправильные глаголы;
- первый промах = «Исправить ответ» без потери жизни;
- реальная развилка хотя бы в 1–2 местах диалога (следующий вопрос зависит от ответа).

## 5. Правила владельца (кратко; полный список в передача-контекста.md)

- Без одобрения в рабочий код ничего не уходит (Правило 50).
- В конце захода: Исправил / Добавил / Не получилось.
- Сначала признать баг → воспроизвести → показать фактами → чинить.
- Один файл = одна зона; `index.html` не перезаписывать без спроса; `original/` не трогать.
- Не выкидывать: онбординг, цели, карту 5 этапов, профиль, сохранение, сноски.
- Стиль взрослый: без совы/конфетти/детских маскотов.
- Жизни — сердечки Apple-эмодзи; срыв = продолжение с места, не сброс.
- Шрифт локальный Inter без CDN.
- Продукт — Telegram mini app (не сайт). Токены GitHub — только env, в файлы не писать; после заливки напоминать отозвать.
- Скрины владельца: агент без зрения читает их OCR-ом (текст), рисунки/стрелки — не видит; просить словами.

```bash
git clone --branch workspace https://github.com/Greed-webdev/contextflow.git
# или, если репозиторий приватный — владелец даст токен (env, не в файлы)
cd contextflow
node serve.js          # локальный сервер на 0.0.0.0:8080
# проверки: python3 /tmp/... — стенды надо пересоздать по описанию в §3
```

После правок: коммит в `workspace`; заливка сайта: `GH_TOKEN=... ./обновить-сайт.sh` (main-ветку руками не трогать — её пересоздаёт скрипт).
