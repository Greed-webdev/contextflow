# Как работает судья свободных ответов (ветвящиеся диалоги)

Коротко: **нет, это не точное совпадение**. Судья никогда не сравнивает твой ответ
с эталоном `best`. Он разбивает ответ на слова и ищет в них **смысловые маркеры**
(ключевые слова). Порядок слов не важен, лишние слова игнорируются.
«Строгий» он в другом смысле: полностью детерминированный — один и тот же ответ
всегда даёт одну и ту же ветку, без случайности.

---

## Конвейер из 4 шагов

### 1. `norm()` — очистка

```js
const norm = t => (t||'').toLowerCase()          // в нижний регистр
  .replace(/[\u2019']/g,"'")                      // «умный» апостроф → обычный
  .replace(/[^a-z' ]/g,' ')                       // вся пунктуация и цифры — вон
  .split(/\s+/).filter(Boolean);                  // разбить на массив слов
```

`"Hi! I'm Anna, I have a meeting."` → `['hi',"i'm",'anna','i','have','a','meeting','.']`

### 2. `expand()` — разворот сокращений

```js
const EXP = { "i'm":['i','am'], "don't":['do','not'], "i've":['i','have'],
              "what's":['what','is'], "i'll":['i','will'], ... };
const expand = a => { const o=[]; a.forEach(x=>{
  if(EXP[x]) o.push(...EXP[x]); else o.push(x.replace(/'/g,''));
}); return o; };
```

`i'm` → `i am`, `don't` → `do not`. После этого судья «видит» глагол `am`,
хотя пользователь его не писал.

### 3. `has()` — поиск маркеров **по наличию**, не по совпадению

```js
const has = (w,...xs) => xs.some(x => w.includes(x));
```

`has(w,'meeting','appointment')` = «есть ли в ответе слово *встреча* или *приём*».
Не важно, где оно стоит и что вокруг.

### 4. Вердикт судьи узла

Судья проверяет маркеры по приоритету и возвращает:
- `{br:'имя_ветки'}` — в какую ветку графа идти;
- `{huh:1}` — смысл не распознан → собеседник переспросит.

## Живой пример — первый узел сцены в офисе

Твоя задача: поздороваться, назваться, сказать зачем пришёл.
Ответ: `«Hi! I'm Anna, I have a meeting.»`

| шаг | что происходит |
|---|---|
| norm | `['hi','i'm','anna','i','have','a','meeting']` |
| expand | `['hi','i','am','anna','i','have','a','meeting']` |
| pickName | вытаскивает `anna` (отсеяв служебные слова) → `mem.name='Anna'` |
| has(…,'meeting') | ✅ найдено |
| отрицание? | нет («no/not» рядом с делом нет) |
| вердикт | `{br:'meet_full'}` |

Результат: админ говорит *«Nice to meet you, Anna. The meeting is in room 204…»* —
и имя уже подставлено из памяти.

Тот же вердикт дали бы: `«Hello, Anna here for the meeting»`, `«meeting, i am anna»`,
`«I have an appointment, Anna»` — точной фразы нет нигде.

А вот `«I have no meeting, just looking around»` → судья увидит `no` рядом с
`meeting` (и это не оборот типа «no problem») → ветка `leave`: вас вежливо проводят.

## Специальные помощники (не просто слова)

- **`negatedAt(w,i)`** — «слово №i стоит под отрицанием?». Проходит от `no/not`
  вперёд сквозь мусор (`to, a, the, want, can…`), но гаснет на вежливых
  оборотах (`no problem`, `no worries`, `not sure`).
- **`numOf()` / `FLOWNUM`** — собирают числа из слов: `two hundred four` → `204`.
  Узел «переспроси дорогу» засчитает ответ, только если 204 реально названо.
- **`pickName()`** — извлекает имя из фразы по белому/чёрному спискам.
- **`DAY_IN()`** — ловит день недели (нужно для сцен с датами).

## Более мягкий вариант судьи: три уровня

В «живой логике» (сценарий с потерей вещи) судья не бинарный, а трёхуровневый:

| уровень | смысл | пример |
|---|---|---|
| `ok` | полная фраза, всё по задаче | «I lost my phone at the cafe» |
| `short` | принято, но с пометкой | просто «phone» → «Понял. Целой фразой яснее.» |
| `no` | блок, собеседник уточнит | ответ по-русски или мимо темы |

То есть одно слово тоже двигает диалог вперёд — просто с комментарием.

## Защита от тупика

- `huh` → собеседник переспрашивает; подсказка появляется **только после 2 непониманий**;
- кнопка «Не знаю» → проговаривается эталон `best`, диалог продолжается;
- конец сцены — только через прощание (`next:null` у узлов прощания);
- всё исполняется в браузере, офлайн, без сервера и без ЛЛМ — поэтому результат
  на 100% воспроизводим и покрыт автотестами (`qa/flow-test.js`, сотни путей).
